- 저장소: `doguri25/social`
- 참고 프로젝트: `doguri25/pokju-edu` (폭주 구구단). 같은 빌드 방식(조각 파일을 이어 붙여 파일 하나로)을 쓴다.
- 참고 교육과정: 『한국형 사회정서교육 교육과정』(17개 시·도교육청, 2025 TR-27)

## 1. 한 줄 요약

사회정서를 다루는 동화 5권을 **3D 디오라마 무대**와 **웹툰 컷**으로 보여 주고, 사건마다 아이가 **행동을 골라 이야기의 결과가 달라지는** 초등 3~4학년 수업용 게임.

## 2. 왜 만드는가

- 사회정서 수업은 "이럴 때 어떻게 할까?"를 묻는 일이 많은데, 글로만 읽으면 아이들이 정답처럼 보이는 답을 고르고 끝낸다.
- 내가 고른 행동 때문에 친구의 표정과 이야기의 끝이 바뀌는 것을 **직접 보면**, 선택과 결과의 관계를 몸으로 느낀다.
- 다른 선택을 다시 해 보고 결과를 비교할 수 있어서 "그때 다르게 했다면?"을 이야기하기 좋다.
- 폭주 구구단에서 이미 만든 3D 화면, 터치 조작, 화질 조정, 효과음, 기기 저장, 수업 링크, 파일 하나로 묶는 빌드를 그대로 가져올 수 있다.

## 3. 엔진 선택

### 3.1 비교

| 후보 | 좋은 점 | 아쉬운 점 |
| --- | --- | --- |
| Three.js r128 | 폭주 구구단과 같은 엔진이라 코드와 빌드를 그대로 가져옴. 내려받는 크기 약 150KB(gzip). 파일 하나로 묶임. 크롬북에서 가벼움 | 캐릭터 동작, 윤곽선, 화면 캡처를 직접 짜야 함 |
| **Babylon.js 9.x** | 화면 밖 찍기, 돌려 보는 카메라, 윤곽선, 그늘·빛 번짐 후처리, glTF 읽기가 기본 제공 | 내려받는 크기 약 1.84MB(gzip), r128의 약 12배. 폭주 코드를 다시 써야 함 |
| Unity WebGL | 편집기로 장면을 만들기 쉬움 | 빌드가 수십 MB, 학교 기기에서 로딩이 느림. 파일 하나와 아티팩트 게시가 안 됨 |

### 3.2 결정

**Babylon.js 9.27.1** (`https://cdn.jsdelivr.net/npm/babylonjs@9.27.1/babylon.js` + glTF 읽기 `babylonjs-loaders`, SRI 해시로 고정).

- 바뀐 과정 (모두 2026-10-09): Babylon.js → Three.js r128(가벼움, 폭주 구구단 코드) → Three.js 0.186 + 후처리 → 목업 화면 체험판을 Babylon으로 만든 뒤 **게임 전체를 Babylon으로 옮김**.
- 엔진 파일이 크다 (약 8.9MB, gzip 약 1.8MB). 반 전체가 처음 한꺼번에 받으면 느릴 수 있어 학교 기기 시험(14장 M5)에서 꼭 확인한다. 두 번째부터는 브라우저 저장소에서 읽는다.

| 필요한 것 | Babylon에서 쓰는 방법 |
| --- | --- |
| 그림책 같은 면 처리 | 무광 `StandardMaterial`, 하늘빛 + 햇빛, 부드러운 그림자(PCF), 화질 「높음」에서 SSAO2 그늘과 빛 번짐 |
| 윤곽선 | `mesh.renderOutline` (인물, 가구) |
| 표정 | 얼굴에 `DynamicTexture`(캔버스)를 `CreateDecal`로 붙이고 눈·눈썹·입을 그림 |
| 웹툰 컷 만들기 | 컷마다 카메라를 따로 두고 `CreateScreenshotUsingRenderTargetAsync`로 찍은 뒤 망점(스크린톤)을 입혀 `<img>`로 씀 |
| 글자, 버튼, 말풍선 | 3D 안에 넣지 않고 HTML과 CSS로 위에 겹침 (한글 글꼴, 읽어 주기, 글자 크기 조절이 쉬움) |
| 무대 돌려 보기 | `ArcRotateCamera` (끌기, 두 손가락, 휠, 방향키). 카메라 쪽 벽은 저절로 걷힘 |
| 가구, 나무, 집 | Kenney CC0 모델(glb)을 빌드 때 페이지 안에 넣음 |

Babylon 9.27을 쓰며 알게 된 점 (코드 주석에도 있음):
- 오른손 좌표계(`useRightHandedSystem`)에서 판 그림이 좌우로 뒤집혀 UV 를 되돌린다.
- 후처리가 없는 카메라로 화면 밖 찍기를 하면 빈 그림이 나와, 컷 카메라에 그대로 옮기는 후처리(`PassPostProcess`)를 붙인다.
- 윤곽선이 부풀린 깊이를 앞면에 써서, 표면에 붙은 얼굴 무늬와 종이는 윤곽선 두께보다 바깥에 둔다.
- `onNewMeshAddedObservable` 은 늦게 불려 인물 층(layerMask)을 덮어써서 쓰지 않는다.

## 5. 사회정서 교육과정 연결

### 5.1 다루는 역량

교육과정의 네 역량(자기인식·관리, 소통·협력, 책임, 마음돌봄)과 초등 목표를 따른다.

- 자기인식·관리: 자신의 감정과 행동을 이해하고 긍정적인 자기 인식을 기른다.
- 소통·협력: 타인의 말을 경청하며 배려하고 협력하는 기본 태도를 기른다.
- 책임: 자신이 맡은 일을 성실히 수행하며 규칙을 지키는 태도를 기른다.
- 마음돌봄: 자신의 감정을 소중히 여기고, 감정이 힘들 때 스스로 위로하거나 도움을 요청할 수 있다.

## 6. 핵심 놀이 방식

### 6.1 한 권의 흐름 (10~15분)

1. **책장**: 3D 책장에 책 5권이 꽂혀 있다. 한 권을 누르면 책이 열리며 첫 무대로 들어간다.
2. **무대 둘러보기**: 디오라마(작은 3D 무대: 교실, 운동장, 놀이터, 집, 도서관 등) 위에 인물이 서 있다. 손가락으로 끌어 무대를 돌려 본다. 빛나는 인물이나 물건을 누르면 속마음 말풍선이나 단서가 나온다.
3. **무대 옆 웹툰 컷**: 한 화면에 왼쪽은 3D 무대, 오른쪽은 지금 컷(그림, 말풍선, 글)과 할 일 칸이 함께 있다. 「다음」으로 한 컷씩 넘기고 「이전」으로 그 장면의 지난 컷을 다시 본다. 무대의 인물도 지금 컷의 표정과 자세를 한다.
4. **마음 살피기**: 고르기 전에 「지금 ○○의 마음은?」 감정 카드를 고른다 (6.3).
5. **고르기**: 행동 2~3개 가운데 하나를 고른다.
6. **결과**: 고른 행동에 따라 다른 웹툰 컷이 이어지고, 무대로 돌아오면 결과가 남아 있다 (친구의 표정, 함께 앉은 자리, 열린 길 등).
7. 3~6을 권마다 3번 한다.
8. **결말**: 결말 3종 가운데 하나를 본다 (7.3).
9. **돌아보기**: 「내가 고른 길」 지도에서 지나온 장면과 고른 것을 본다. 아직 못 본 길은 흐리게 보인다. 아무 갈림길이나 눌러 다른 선택을 해 볼 수 있다.

### 6.2 무대 (3D 디오라마)

- 무대 하나는 둥근 나무 받침 위에 올린 작은 세트다. 방은 벽 4면, 소품, 인물 2~5명.
- 카메라는 무대를 비스듬히 내려다보며 360도 돌아간다. 위아래와 확대는 제한한다. 카메라 쪽 벽은 스르르 사라져 늘 안이 보인다.
- 걸어 다니는 캐릭터는 없다. 조작은 끌기와 누르기뿐이다.
- 소품(책상, 의자, 나무, 미끄럼틀, 책장 등)은 공용 소품 모음을 만들어 다섯 권이 함께 쓴다. 모두 코드로 만들고 모델 파일은 쓰지 않는다 (폭주 구구단의 차와 같은 방식).

### 6.3 감정 카드

- 감정 8개: 기쁨, 슬픔, 화남, 걱정, 놀람, 부끄러움, 서운함, 편안함.
- 카드마다 얼굴 그림, 글자, 색을 함께 쓴다. 색을 구분하기 어려워도 읽힌다.
- 점수를 매기지 않는다. 고르고 나면 「○○는 사실 이런 마음이었대」 하며 인물의 속마음 컷을 하나 보여 준다. 아이가 고른 감정이 다르면 「그렇게 느낄 수도 있어」라고 말해 준다.
- 성취기준 [2정서03-01](감정의 종류를 알고 말로 설명하기)을 3~4학년에서 복습하는 구실도 한다.

### 6.4 고르기

- 선택지는 2~3개. 모두 아이가 실제로 할 법한 행동으로 쓴다 (예: 모른 척하기, 바로 따지기, 먼저 물어보기).
- 고르기 화면에는 시간 제한이 없다.
- 고른 뒤 「정답!」, 「틀렸어요」 같은 말은 없다. 결과는 이야기 속 인물의 반응으로만 보여 준다.

### 6.5 원작에 갈림길을 넣는 방법

원작 그림책은 한 줄로 이어지는 이야기라 갈림길이 없다. 원작의 줄거리와 마지막 장면을 지키면서 고를 거리를 만들기 위해 두 가지를 섞는다 (2026-10-09 결정).

| 종류 | 어디에 | 고르면 |
| --- | --- | --- |
| 만약에 | 원작에서 인물이 실수하는 순간 (1권: 3면 색연필, 4면 「지워 줘」, 9면 전해 들은 말) | 원작과 다른 쪽을 고르면 점선 테두리의 「만약에…」 컷 1~2개를 보고 「하지만 이야기 속 유나는…」으로 원작에 돌아온다. 원작과 같은 쪽을 고르면 「이야기 속 유나도 그렇게 했어요」만 보여 준다. 줄거리는 바뀌지 않는다 |
| 진짜 갈림길 | 사건 뒤 회복하는 과정 (1권: 13면 계단, 15면 밤, 17면 사과) | 고른 쪽의 장면으로 가고 표시가 쌓인다. 결말이 달라진다 |

17면 사과는 선택지 하나가 아니라 「하고 싶은 말 고르기」다. 말 조각 여러 개를 골라 유나가 차례로 말한다. 원작의 말 조각을 모두 고르면 원작 17~18면과 같아진다.

### 6.6 숨 고르기

원작 13면과 16면의 「한 번, 두 번, 세 번」 숨쉬기를 아이가 직접 한다. 동그라미를 누르고 있으면 커지며 들이쉬고, 떼면 작아지며 내쉰다. 세 번 하면 이야기가 이어진다. 선생님용 「건너뛰기」가 있다.

## 7. 내용 원칙

### 7.1 폭력 없음

- 갈등은 말과 마음에서만 일어난다. 때리기, 밀치기, 물건 던지기, 위협하는 몸짓은 그리지 않는다.
- 놀림, 따돌림 같은 상황은 다루되, 상처를 주는 말을 그대로 크게 쓰지 않고 말풍선을 흐리게 하거나 「(속상한 말)」처럼 줄인다.
- 게임 오버, 벌점, 체력은 없다.

### 7.2 아쉬운 결과도 배움이 되게

- 아쉬운 선택의 결과도 「그래서 이렇게 됐다」에서 끝나지 않고 「다음에는 어떻게 해 볼까?」 컷으로 이어진다.
- 아쉬운 결말 뒤에는 「그 장면으로 돌아가기」 버튼이 바로 나온다.

### 7.3 결말 3종

| 결말 | 뜻 |
| --- | --- |
| 마음이 이어진 결말 | 서로의 마음을 알고 관계가 더 좋아짐 |
| 보통 결말 | 일은 해결됐지만 마음 한구석이 남음 |
| 아쉬운 결말 | 오해가 남음. 「다음에는?」 컷과 되돌아가기로 이어짐 |

## 8. 분기 구조

### 8.1 갈래-모임형

선택마다 장면이 다 따로 갈라지면 장면 수가 2배, 4배로 늘어 다섯 권을 쓸 수 없다. 그래서 **갈래-모임형**으로 만든다.

- 고르면 바로 그 선택만의 장면(갈래)이 1~2개 나온다.
- 그 뒤 이야기의 큰 줄기(모임)로 다시 모인다.
- 고른 것은 **표시(flag)** 로 남는다. 예: `listen` +1, `blame` +1.
- 뒤 장면은 표시에 따라 대사나 인물 표정이 조금씩 달라진다.
- 결말은 마지막에 표시를 보고 정한다.

```
[시작] → 사건1 ─┬ 갈래 1a ┐
                └ 갈래 1b ┴→ 사건2 ─┬ 갈래 2a ┐
                                     ├ 갈래 2b ┤
                                     └ 갈래 2c ┴→ 사건3 ─┬ … ┴→ 표시로 결말 고르기
```

### 8.2 한 권의 분량 기준

| 항목 | 기준 |
| --- | --- |
| 갈림길 | 3개 |
| 장면 | 10개 안팎 (모임 장면 4, 갈래 장면 6~7) |
| 웹툰 컷 | 장면당 3~6컷, 한 권 약 40컷 |
| 결말 | 3개 |
| 한 번 읽는 시간 | 10~15분 |

## 9. 웹툰 연출

### 9.1 화면 배치

- 무대와 컷이 한 화면에 함께 있다 (목업 화면). 데스크톱·전자칠판은 왼쪽 무대 + 오른쪽 컷과 할 일, 휴대전화는 무대 위 + 컷과 할 일 아래.
- 고를 것(갈림길, 감정 카드, 말 고르기)이 나오면 컷 그림이 줄어들어 화면이 세로로 넘치지 않는다.
- 장면이 바뀌면 컷 자리에 「○면 · 장소 · 이야기 마디」 첫 장이 나오고, 무대를 둘러본 뒤 「이야기 보기」로 시작한다.

### 9.2 컷 그림 (섞어서)

| 컷 | 만드는 방법 |
| --- | --- |
| 평소 컷 (대부분) | 무대의 인물을 컷마다 다른 카메라 각도, 표정, 자세로 바꿔 놓고 한 번 그려서 찍는다. 툰 재질과 윤곽선으로 만화처럼 보인다. 인물 생김새가 컷마다 늘 같다 |
| 표지, 결말 컷 | 그림 파일. 권당 4장 이하, 장당 webp 150KB 이하 |

- 카메라 각도 4종: 무대 전체(`wide`), 두 사람(`two`), 얼굴 가까이(`close`), 어깨 너머(`over`).
- 감정에 따라 컷 배경 색조와 효과선(놀람: 집중선, 걱정: 물결선 등)을 더한다.
- 말풍선 3종: 말(둥근), 속마음(구름), 크게 말함(뾰족). 크게 말함도 7.1을 지킨다.
- 그림 파일은 `assets/`에 따로 두고 그 책을 열 때 불러온다. `index.html` 안에 넣지 않는다 (아티팩트 16MB 한도, 첫 로딩 속도 때문).

## 10. 수업에서 쓰기

### 10.1 1인 1기기 (기본)

- 학생이 태블릿이나 크롬북으로 각자 읽는다.
- 교사는 「수업 링크 만들기」로 책을 정해 준다. 예: `?book=2`, 다른 길 보기를 막으려면 `?book=2&replay=off`.
- 수업 링크로 열면 책장을 건너뛰고 그 책 첫 무대로 들어간다.

### 10.2 함께 보기 (전자칠판)

- 설정이나 링크 `?book=2&mode=class`로 켠다.
- 글자가 커지고, 무대 조작은 교사만 한다.
- 고르기 장면에서 멈추고 다음을 보여 준다.
  1. 교사용 질문 (이야기 JSON의 `ask`). 예: 「민우가 왜 대답하지 않았을까요?」
  2. 생각 시간 타이머 30 / 60 / 90초.
  3. 선택지마다 손든 사람 수를 세는 +, - 버튼.
  4. 교사가 한 선택지를 눌러 확정한다 (다수결을 강제하지 않음).
- 결말 뒤 「다른 길 비교」: 반이 고른 길과 다른 길의 결말을 나란히 보여 준다.

### 10.3 기록

- 이 기기에만 `social-v1` 이름으로 저장한다. 어디로도 보내지 않는다. 이름이나 개인 정보를 받지 않는다.
- 저장하는 것: 권마다 본 결말, 마지막으로 고른 길, 감정 카드 답.
- 책장에서 권마다 본 결말 수(예: 2/3)를 보여 준다.
- 설정에 「기록 지우기」가 있다.

## 12. 기술 방향

### 12.1 파일 구조 (폭주 구구단과 같은 방식)

| 경로 | 내용 |
| --- | --- |
| `index.html` | 바로 열 수 있는 완성 파일 (GitHub Pages 용) |
| `data/defs.json` | 무대별 자리·물건·카메라, 표정·자세 이름 목록. 빌드할 때 `@defs` 자리에 들어감 |
| `dist/artifact.html` | Claude 아티팩트에 게시하는 본문 조각 |
| `src/` | 소스 조각. `build.sh`에 적힌 순서로 이어 붙음 |
| `stories/book1.json` ~ `book5.json` | 이야기 데이터. 빌드할 때 `@stories` 자리에 들어감 |
| `assets/` | 표지, 결말 그림 (webp) |
| `tests/story.test.js` | 이야기 데이터 검사 |
| `tests/browser.test.mjs` | 브라우저로 끝까지 넘겨 보는 시험 |
| `build.sh` | 조각을 이어 붙여 위 두 파일을 만듦 |

### 12.2 이야기 데이터 형식

선생님이 글만 고쳐도 이야기를 바꿀 수 있게, 그림 정보도 글자로 적는다. 실제 예시는 `stories/book1.json`. 쓸 수 있는 무대, 자리, 표정, 자세, 카메라 이름은 `data/defs.json`에 모여 있다.

```json
{
  "id": "book1", "title": "(제목)", "start": "s01",
  "cast": [{ "id": "yuna", "name": "유나", "top": "#f28b74", "inner": "#fff7ee", "pants": "#5b6b8c", "hair": "bob", "hairColor": "#4a3326", "card": "#d3f0e1", "intro": "인물 카드를 누르면 나오는 소개" }],
  "scenes": {
    "s03": {
      "stage": "classroom", "page": "3면", "place": "월요일 · 교실", "part": "기 · 우리 사이",
      "set": { "cast": { "yuna": "seat_w sit joy", "seoa": "seat_nw sit joy" }, "map": "school", "pencils": "open" },
      "explore": [{ "on": "map", "text": "무대에서 누르면 나오는 말" }],
      "panels": [
        { "shot": "item", "on": "pencils", "cap": "원고 글 (그림 아래)" },
        { "whatif": { "q": "질문", "ask": "선생님 질문", "opts": [{ "text": "다른 행동", "panels": [] }, { "text": "원작 행동", "story": true }], "same": "…", "back": "하지만 이야기 속 유나는…" } },
        { "shot": "two", "on": ["seoa", "yuna"], "faces": { "seoa": "worried" }, "lines": [{ "who": "seoa", "say": "그거… 새 건데." }] },
        { "feel": { "who": "seoa", "q": "서아의 마음은?", "is": ["hurt", "worried"], "reveal": "속마음 한 줄" } }
      ],
      "go": "s04"
    }
  },
  "endings": [{ "id": "warm", "kind": "good", "title": "다시 이어진 길", "when": { "repair": 2, "listen": 1, "blame": { "max": 0 } }, "panels": [] }]
}
```

- `set.cast` 는 `"자리 자세 표정 [크기]"`. 장면의 `set` 은 무대 전체를 새로 정하고, 컷 목록 안의 `{ "set": … }` 은 지금 상태에 덧씌운다 (인물을 빼려면 `"hide"`). `{ "stage": "kinder", "set": … }` 처럼 무대를 바꾸면 웹툰을 보는 동안 몰래 바뀐다 (회상 컷).
- 그림 컷: `shot` (`wide` 무대 전체, `group` 여럿, `two` 두 사람, `close` 얼굴, `over` 어깨 너머, `item` 물건, `high` 내려다보기), `on`, `angle` (카메라를 돌리는 각도), `faces`·`poses` (그 컷에서만), `pre` (그림 위 글), `cap` (그림 아래 글), `lines` (`say` 말, `think` 속마음, `shout` 크게, `whisper` 작게), `sfx` (큰 글자 효과음), `fx` (`focus`, `gloom`, `heat`, `sparkle`), `tone` (`memory` 회상, `whatif` 만약에).
- 글 컷 `{ "text": … }`, 휴대전화 컷 `{ "phone": { "chat": … } }` 또는 `{ "phone": { "profile": { "name": "유나", "photo": { 그림 컷 } } } }`.
- 활동: `{ "feel": … }` 감정 카드, `{ "activity": "breathe" }` 숨 고르기.
- 장면 끝: `go` (다음 장면), `choices` (진짜 갈림길, 고르면 `add` 로 표시를 더함), `compose` + `end: true` (말 고르기 뒤 결말).
- 표정 이름: 감정 카드 8개(`joy`, `sad`, `angry`, `worried`, `surprised`, `shy`, `hurt`, `calm`)와 그림용 `laugh`, `yawn`, `cry`.
- 조건 `when`: `{ "repair": 2 }` 는 2 이상, `{ "blame": { "max": 0 } }` 은 0 이하. 결말은 위에서부터 조건이 맞는 첫 결말, 마지막 결말은 조건 없는 기본 결말. 말 조각의 `when` 으로 앞의 선택에 따라 보이는 말을 바꾼다.

### 12.3 이야기 데이터 검사

`node tests/story.test.js`가 모든 책 JSON을 검사한다. 내용을 넣거나 고친 뒤 반드시 돌린다.

- 모든 `go`가 있는 장면을 가리키는지.
- 시작에서 갈 수 있는 모든 길이 결말에 닿는지 (막다른 장면이 없는지).
- 아무 데서도 오지 않는 장면이 없는지.
- 마지막 결말에 `when`이 없는지 (어떤 길이든 결말이 정해지는지).
- 표정 이름, 카메라 각도, 무대 이름이 정해진 목록 안에 있는지.
- 인물 `id`가 `cast`에 있는지.
- 분량이 8.2 기준 안인지 (넘으면 경고만).
- 갈림길과 말 조각의 모든 조합(1권은 1527가지)을 따라가 모두 결말에 닿는지, 결말 세 개가 모두 나오는지.

`node tests/browser.test.mjs [warm|okay|sorry] [phone] [every]` 는 화면 없는 크롬으로 책을 처음부터 끝까지 넘겨, 고른 결말에 닿는지와 콘솔 오류가 없는지 본다. Babylon과 글꼴은 node 가 받아 `tests/.cache/` 에 두고 넘겨 주므로 두 번째부터는 인터넷이 끊겨도 돌아간다. 교실 첫 장면에서 둘러보기 점, 무대 돌리기(벽 걷힘), 이전 컷도 확인한다.

### 12.4 캐릭터

- **2등신 SD 캐릭터.** 아이는 키 약 1.09m에 머리 지름 0.54m(키의 절반), 어른은 키 약 1.42m(머리 약 2.8개). 머리(구), 몸(캡슐), 짧은 팔다리(캡슐, 팔꿈치·무릎 관절), 윤곽선.
- 머리 모양 5가지(단발, 긴 머리, 똥머리, 곱슬, 짧은 머리)와 안경. 옷 색과 머리 모양은 `cast` 에 적는다.
- 얼굴은 캔버스에 눈, 눈썹, 입, 볼 홍조를 굵게 그려 표정 11개를 만든다 (디오라마 거리에서도 보이게).
- 자세 16개는 관절 각도로 만든다. 뼈대 애니메이션은 쓰지 않는다. 숨 쉬기와 제자리 걷기만 움직인다.

### 12.5 성능

- 목표 기기: 학교 크롬북, 보급형 안드로이드 태블릿, 아이패드.
- 무대 하나에 메시 50개 이하, 움직이지 않는 소품은 합친다.
- 화질 「높음」은 그늘(SSAO2)과 빛 번짐, 「낮음」은 둘 다 끄고 화면 해상도를 낮춘다. 「자동」은 처음 90장이 느리면 낮음으로 바꾼다.
- 무대를 돌리지 않고 가만히 있으면 그리기를 멈춘다 (배터리, 발열).
- 크기 목표: `index.html` 1MB 이하, 첫 화면까지 내려받는 양(엔진, 글꼴 포함) 1.5MB 이하. 그림 파일은 권을 열 때 그 권 것만 받는다.

### 12.6 읽기 도움

- 읽어 주기: 브라우저의 음성 합성(`speechSynthesis`, 한국어 목소리)으로 말풍선을 읽는다. 한국어 목소리가 없는 기기에서는 버튼을 숨긴다.
- 글자 크기 3단계.
- 컷은 아이가 누를 때만 넘어간다 (자동으로 넘기지 않음).
- 키보드로도 모두 할 수 있다 (Tab, Enter, 화살표).
- 배경음악은 기본으로 꺼져 있다 (교실에 기기가 많기 때문).

## 13. 성공 기준
